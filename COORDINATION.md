# Coordination contract

The uppercase requirement words MUST, MUST NOT, SHOULD and MAY follow [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119).

1. **Keep separate missions.** The port orchestrator MUST advance the clean native engine and original game flow. The decomp orchestrator MUST own calculation/matching, recipe cutover, source structure and clean C. Cake Taste supports both through bounded experiments and measured evidence; neither mission replaces the other.
2. **Respect ownership.** Each path MUST have one writer. The receiving owner decides integration. A handoff MUST NOT imply permission to edit another lane's source, runtime or shared tools. Changes cross that boundary as reviewed patches or evidence.
3. **Ask bounded questions.** A repro request SHOULD identify one uncertain behavior, pinned inputs and the required output. Cake Unbake supplies objective facts and checks; Recipe Maker supplies LLM-driven recipe work. Cake Taste MUST consume both directly and keep generated candidates distinct from verified results.
4. **Make evidence inspectable.** Handoffs MUST identify the target version and ROM hash, code/tool revisions, public input and output, proved scope, evidence location and remaining gap. Published proof artifacts MUST be immutable, hash-identified and read back before their final receipt is announced. A prototype or test count MUST NOT stand in for public integration. Verified ROM assets, addresses and game knowledge SHOULD flow back to the owning decomp and port lanes.
5. **Keep metrics honest.** Decomp reports MUST distinguish published genuine C, recovered debt, SDK classification and private candidates. Port reports MUST distinguish implemented helpers, actual startup progress and playable flow. Experiments establish only their measured scope.
6. **Keep one journal integrator.** Verified port, decomp and recomp wins MUST reach the designated journal integrator as evidence or reviewed patches. Other lanes MUST NOT write that journal tree. Project configuration identifies the integrator and path ownership.
7. **Keep orchestration thin.** Messages MUST concern blockers, decisions, useful evidence handoffs or completion. Detailed reasoning and measurements belong in files. Orchestrators MUST NOT send heartbeat/polling chatter or introduce a separate coordination service. Live narration MUST describe actual actions and results.
8. **Reload guidance.** At session start, immediately after every context compaction, and before every hourly strategy review, the agent MUST reread this file, the actual configured Claude Prose/Lexicon hook documents, global AGENTS/RTK instructions and the active handoff. The reviewer MUST compare verified progress with its prior check, restate each lane's own mission, and recommend the next bounded assignments.

9. **Apply the same generic bar.** Tools MUST use explicit current public contracts for any N64 project; game facts are inputs, never tool branches. Platform/compiler quirks belong in symmetric adapters. Retired routes and stores MUST be removed after reviewed artifact migration/readback. For defects, require a smallest real public reproduction, repair at the owning boundary, focused durable state/work/resource checks without timing assertions, one audit, and real public end-to-end proof. New workaround flags, project exceptions and coordination frameworks MUST NOT replace that work.
